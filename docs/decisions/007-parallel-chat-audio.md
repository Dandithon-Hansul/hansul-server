# 007. 채팅 전체 음성과 분석의 병렬 실행

## 배경

기존 채팅은 문장별 음성을 SSE로 보낸 뒤 전체 답변을 다시 합성하고 분석까지 마쳐야 `done`을 보냈다. 004 결정은 전체 음성을 별도로 합성해 보관한다. `done.audio_url`은 클라이언트가 전체 음성을 받는 유일한 공개 경로다.

## 결정

텍스트 생성이 끝나면 전체 음성 합성을 시작한다. 문장별 음성 작업과 답변 저장이 끝나면 분석과 전체 음성 저장을 병렬로 진행한다. 저장된 assistant 메시지의 음성 URL을 갱신하고 분석도 마친 뒤 `done`에 전체 음성 URL을 넣는다. 분석 완료 전 다음 채팅이 시작되는 상태 유실을 막고 기존 `done.audio_url` 계약을 유지한다.

## 대안과 선택 이유

- 전체 음성을 `done` 이후 백그라운드에서 만들면 완료 이벤트는 빠르지만 현재 공개 API로는 나중에 URL을 받을 수 없다.
- 기존처럼 전체 음성 저장 후 분석을 시작하면 API 계약을 유지하나 두 작업의 대기 시간이 더해진다.
- 전체 음성을 없애면 TTS 비용은 줄지만 004의 보관 목적을 충족하지 못한다.

## 결과

전체 음성의 합성·저장이 분석보다 오래 걸리면 `done`은 여전히 이를 기다린다. 병렬 실행으로 분석과 전체 음성의 대기 시간 합산을 줄일 수 있지만 실제 개선 폭은 운영 환경 측정이 필요하다. 전체 음성 저장을 위해 메시지의 음성 URL을 한 번 더 갱신한다. TTS 실패 시 기존처럼 오류 이벤트를 보내고 `done.audio_url`은 null이다.
