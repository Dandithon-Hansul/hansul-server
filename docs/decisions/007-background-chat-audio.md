# 007. 채팅 전체 음성 생성 시점

## 배경

기존 채팅은 문장별 음성을 SSE로 보낸 뒤 전체 답변을 다시 합성하고 저장해야 `done`을 보냈다. 전체 합성은 이미 전달된 문장 음성을 재생하는 데 필요하지 않지만 완료 이벤트를 지연시킨다. 기존 004 결정은 전체 음성을 별도로 합성해 보관한다.

## 결정

문장별 음성과 답변 저장 및 분석은 기존 순서를 유지한다. `done`에는 저장된 메시지 ID와 `audio_url: null`을 보내고 스트림을 닫는다. 전체 음성 합성과 메시지의 음성 URL 갱신은 Next.js `after` 작업에서 수행한다. 소유 레시피와 assistant 메시지 ID를 확인한 뒤 URL을 갱신한다. 이 결정은 004의 전체 음성 별도 합성 방침을 유지하면서 실행 시점만 바꾼다.

## 대안과 선택 이유

- 기존처럼 전체 음성을 기다리면 `done` 지연이 지속되지만 완료 시 URL을 바로 제공할 수 있다.
- 전체 음성을 없애면 TTS 비용과 작업량이 줄지만 004의 보관 목적을 충족하지 못한다.
- `done` 뒤에도 SSE를 열어 두면 URL을 나중에 보낼 수 있지만 스트림 수명이 전체 음성 합성 시간만큼 늘어난다.

## 결과

전체 음성은 비동기로 저장되므로 `done.audio_url`은 즉시 사용할 수 없다. 전체 음성 생성에 실패하면 메시지의 `audio_url`은 null로 남는다. 현재 공개 API에는 저장된 채팅 메시지의 음성 URL을 다시 읽는 경로가 없어, 전체 음성 재생을 클라이언트에 제공하려면 별도 조회 계약이 필요하다. 문장별 `audio` 이벤트는 기존대로 즉시 전송한다.
