# 008. 채팅 완료 이벤트와 후속 작업 분리

## 배경

007은 전체 음성과 분석을 병렬 실행하지만 둘 다 끝나야 `done`을 보낸다. 이 동작은 이슈 #62의 마지막 텍스트 청크 뒤 완료 이벤트 지연 제거 기준과 충돌한다.

## 결정

`done`은 assistant 텍스트 저장 완료를 뜻한다. 전체 음성 합성·저장과 분석은 Next.js `after`로 응답 이후 실행한다. `done.audio_url`은 즉시 준비되지 않으므로 null이며, 클라이언트는 `message_id`로 음성 조회 API를 재조회해 URL을 얻는다. 문장별 음성은 기존 SSE로 전달하며, `done` 이후에도 오디오 프레임이 올 수 있으므로 스트림 종료까지 읽는다.

## 대안과 선택 이유

- 007처럼 음성과 분석을 기다리면 기존 `done.audio_url` 계약과 분석 순서를 유지하지만 완료 이벤트가 늦다.
- 음성만 후속 작업으로 옮기면 분석 지연이 그대로 남는다.
- 전체 음성을 없애면 조회 경로는 필요 없지만 004의 보관 목적을 잃는다.

## 결과

`done`의 의미가 텍스트 저장 완료로 바뀌고 오디오 URL은 나중에 조회한다. 분석이 끝나기 전에 다음 채팅이 시작되면 이전 분석을 보지 못할 수 있다. 분석 저장의 기존 stale 검사로 오래된 결과가 최신 메시지를 덮어쓰는 것은 막지만, 이 순서 차이는 실제 연속 채팅에서 검증이 필요하다. 후속 작업은 실행 환경의 함수 제한 시간 안에서만 완료된다. 이 결정은 007의 완료 이벤트 계약을 대체한다.
